# 外部意图（WriteIntent）

> 框架性内容：为什么需要"意图"，以及它带来的死锁陷阱。
> 详细教程见 <https://tags.doc.stdunit.com/>（第 7 章「外部意图」）。

## 为什么需要它

把所有变更都放进逻辑组件（`ProcessAsync`）里最理想：顺序固定、时机可预测。但界面按钮、
上位机/MES 请求、AI（MCP）操作都需要**从循环外部**改变状态。外部直接 `tag.Value = x` 的问题是
**不确定性**：你既不知道这次变更何时会被刷写到底层，也可能与正在读取的循环并发改同一份缓存
（"刚写的值"被这一轮读完的旧值覆盖，反之亦然）。

## 机制

意图 = 一段排进轮询线程、在每轮**第 0 步**按序执行的委托；执行完若缓存已脏，立刻刷写底层。
于是"外部变更"和"循环自身"共享同一个串行上下文，不再有并发不确定性：

```csharp
proj.WriteIntent("入口名", (entry, ct) =>
{
    ack.Value = true;                 // 到达这里时，一定是在该入口的轮询线程上
    return ValueTask.CompletedTask;   // 尽早返回
}, out var task);

await task;   // 可选：等待这个意图"真正执行完"（执行失败会在这里抛出）
```

`WriteIntent` 只是**入队**（每个入口一条队列）；委托要**尽快返回**，否则会拖住同一入口后面的所有逻辑。

## 死锁：环路等待

```text
(循环内) Logicet 发事件给外部 → await 外部处理完成
(循环外) 收到事件 → 处理业务 → WriteIntent(...) → await 该意图执行完成
(循环内) 外部处理完才 ack —— 但循环内正卡在 await 上，LOOP 进不了下一轮
         ⇒ 意图永远排不到第 0 步被执行 ⇒ 死锁
```

一句话记法：**"循环内等外部、外部等意图"必然死锁**。规避方式：

1. **首选**：状态变更全部放进 `ILogicet` 内部，外部只观察事件、不写意图。
2. 外部必须写意图时，内部**不要同步等外部**：把那段等待挪出轮询线程（`Task.Run`，并自行处理异常与去重标志）。
