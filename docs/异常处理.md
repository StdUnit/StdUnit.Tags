## 错误处理

**加载期**（解析 XML、解析地址、构建测点树、执行加载期校验）抛出的错误统一收敛到一个异常族，
调用方一个 `catch` 就能兜住并在启动阶段快速失败：

```text
TagsProjectException                              (abstract) 本库异常基类
└── TagsProjectLoadException                      (abstract) 加载期错误
    ├── TagsProjectXmlException                   XML 属性/元素值不合法（缺属性、未知枚举、数值无法解析……）
    ├── TagsProjectAddressException               地址字符串无法解析（S7 / Modbus / Hjzk / SimpleFiles……）
    ├── TagsProjectConfigurationException         配置语义不自洽（未声明通道、未注册驱动、重名测点、类型不匹配……）
    └── TagsProjectValidationException            加载期校验器聚合错误（Errors 保留全部明细）
        └── TagsProjectSchemaException            XSD 校验（EnableXmlSchemaValidation，默认关闭）
```

```csharp
try
{
    var proj = factory.Create(projRoot);
}
catch (TagsProjectLoadException ex)
{
    // ex.Location 给出出错位置，如 TagGrp(产线1)/TagCbnt(输入)/Tag(bit)、Channel(S7-3)
    logger.LogError(ex, "项目加载失败：{Location}", ex.Location);
}
```

- 校验器（XSD / 交叉引用 / 驱动工厂 / 入口通道独占 / 嵌套入口）**一次性汇总全部错误**，
  因此 `TagsProjectValidationException.Errors` 是列表；`Message` 已把全部条目拼好，直接打日志即可。
- 重名测点、未声明的通道、未注册的驱动等错误都带**完整路径上下文**（`TagGrp(a)/TagCbnt(b)/Tag(c)`），
  不再需要从字典的 "An item with the same key has already been added" 反推是哪个节点出的问题。
  分隔符用 `/`，与 `ITagGrp.Descendant("a/b/c")` 的路径语法一致，便于对照与复制。
- 运行期（读写、连接、清理）异常仍在逐步细化，**不要**假设库抛出的所有异常都派生自 `TagsProjectException`；
  范围与进度见 [backlog.md](../backlog.md) 的“异常细化”条目。

## 决策树：该用哪个异常类型

面向**驱动作者 / 二次开发者**：新代码要报告一个错误时，按下面的树选择类型。

```text
要报告一个错误
├─ 发生在运行期（读写 / 连接 / 轮询 / 清理）？
│   └─ 是 → 运行期异常族尚未定义：用语义最贴近的 BCL 类型
│            (NotSupportedException / TimeoutException / InvalidDataException /
│             OperationCanceledException / SocketException …)
│            不要为了"看起来统一"而把运行期错误塞进 TagsProjectLoadException；
│            进度见 backlog.md 的"异常细化"条目。
└─ 发生在加载期（解析 XML / 解析地址 / 构建测点树 / 执行加载期校验）？
    └─ 是 → 这个错误是怎么被发现的？
        ├─ 读 XML 属性/元素时，这个值本身就不合法
        │   (缺 name/driver 等必填属性；endian/access 是未知枚举；
        │    scanInterval / tagSize / maxlen / Port / Rack / Parity … 解析失败)
        │   └─→ TagsProjectXmlException
        ├─ 把字符串解析成"测点地址"时失败
        │   (S7 的 DB/MB/$$ 地址、Modbus 的 <slave>~<area><start>[.<bit>]、
        │    Hjzk / ZLan 的引脚地址、位地址越界)
        │   └─→ TagsProjectAddressException
        ├─ 由"加载前扫描整个项目"的校验器发现，且一次性汇总多条错误
        │   ├─ 就是 XSD 校验（EnableXmlSchemaValidation）→ TagsProjectSchemaException
        │   └─ 其它校验器（交叉引用 / 驱动工厂 / 入口通道独占 / 嵌套入口 / 第三方）
        │       └─→ TagsProjectValidationException（Errors 保留全部明细）
        └─ 构建测点树的过程中，配置语义不自洽
            (引用了未声明的通道；driver 未注册工厂；同一父节点下测点重名；
             测点种类或地址区域不被该驱动支持；通道类型与测点要求不匹配)
            └─→ TagsProjectConfigurationException
```

### 三条容易判错的边界

| 拿不准的情况 | 怎么选 |
|---|---|
| `endian="Tiny"`（值本身读不出来） vs `channel="S7-99"`（值读得出来，但对不上任何声明） | 前者 `TagsProjectXmlException`；后者 `TagsProjectConfigurationException` |
| S7 地址 `DB200.x`（解析失败） vs DI 测点却配了 4x 寄存器地址（解析成功，但区域不被支持） | 前者 `TagsProjectAddressException`；后者 `TagsProjectConfigurationException` |
| 发现时机是"加载前批量扫描"还是"构建过程中立刻发现" | 批量 + 汇总多条 + 有 `Errors` → `TagsProjectValidationException`；发现即抛、一次一条 → `TagsProjectConfigurationException` |

> 校验器聚合异常（`TagsProjectValidationException`）的 `Location` 为 `null`——
> 它一次报告多处错误，定位信息在 `Errors` 的每一条里，不在顶层。

### 抛异常时的两条硬性要求

1. **消息里必须带定位上下文**，并尽量把它同时填进 `Location`：
   - XML 元素：`element.GetLocationPath()`；
   - 已建好的测点树：`grp.GetLocationPath()`、`grp.GetLocationPath("Tag(bit)")`；
   - 只有通道/描述符时：`$"Channel({descriptor.Name})"`、`$"Tag({descriptor.TagName})"`。

   路径段用 `/` 连接，形如 `TagGrp(产线1)/TagCbnt(输入)/Tag(bit)`、`Channel(S7-3)`。
2. **不要为了分类而分类**：确实不属于任何一类时，就近选一个并把上下文写清楚，
   或直接继承 `TagsProjectLoadException` 表达"加载期失败"。

### 第三方驱动要自定义类型

继承 `TagsProjectXmlException` / `TagsProjectAddressException` / `TagsProjectConfigurationException`，
或直接继承 `TagsProjectLoadException`——它们都能被 `catch (TagsProjectLoadException)` 接住，
不会破坏使用方的统一处理。
