# 扩展点

> 框架性内容：分层与依赖方向、公开面原则、驱动怎么接进来。
> 详细 API 与任务配方见 <https://tags.doc.stdunit.com/assets/999.AI.markdown>。

## 分层

```text
StdUnit.Tags.Core              硬件无关的核心抽象 + 项目 XML 的 schema
└── StdUnit.Tags               项目 / 日志 / 插件 / DI，仍与硬件无关
    ├── 驱动包：S7 / ModbusTcp / OpcUaClient / ComScanner / SimpleFiles / Hjzk / ZLan（后者基于 ModbusTcp）
    ├── McpServer / BlazorLib  把项目暴露给 AI / 界面
    └── RxExtensions / R3Extensions   只依赖 Core，用于订阅测点事件
应用：只引用需要的驱动包 + 接口 + DI 扩展
```

硬件知识全部在驱动包里：新增一种设备 = 新增一个驱动包，Core 与 StdUnit.Tags 不需要改动。

## Public Surface 基本原则

**公开面 = 接口 + DI 扩展 + 工厂/构建器**；具体实现（项目、控制器、运行器、工厂）一律 `internal`。
使用者只通过接口 + DI 使用。所以新增驱动时不要把具体实现 `public` 出去，也不要让调用方自己组装内部服务。

## 驱动接入

- 每个驱动包收口为一个同名扩展类 `.AddXxxSupport()`，提供通道 + 组合测点构建器 + 直接测点构建器 + schema 的组合，并保留细粒度方法以便按需拆分。**新增驱动沿用这个形状。**
- 驱动要实现三类东西：**通道工厂**（driver → `ITagChannel`）、**组合测点构建器**（`<TagCbnt>` 的"一起读、一起写"——缓存布局与地址规整都发生在这里）、**直接测点构建器**（`<Tag>`）。想让编辑器有提示、运行期能校验就再提供一个 **schema provider**（驱动自带 XSD）。

## 加载期校验

加载期是唯一适合"快速失败"的阶段：`channel` 是否指向已声明的通道、`driver` 是否注册了工厂、入口内是否嵌套了 `isEntry`、一个通道是否被多个入口共用——这四条**默认开启**；XML 的 XSD 校验是 opt-in；第三方可 `AddValidation<T>()` 追加自己的校验器，所有校验器**一次性汇总全部错误**。

异常族与消息里的定位上下文见 [异常处理](./异常处理.md)。
