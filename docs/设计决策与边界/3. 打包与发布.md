# 打包与发布

本文件记录**发布机制与打包决策**。1.0 首发到 nuget.org 是这个类库家族第一次公开露面，配套项都是那时补的。
版本号与用户可见变更见 [CHANGELOG](../../CHANGELOG.md)。

## 一、发布流程

- 版本号**不写在 csproj 里**：发版工作流（`workflow_dispatch`，输入 `releaseVersion`）→ `src/publish-packages.ps1 -packageVersion` →
  对 14 个项目逐个 `dotnet pack -c Release -p:PackageVersion=…` + `nuget push`。
- 两个入口，用途不同：
  - **`release-nuget.yml`（`name: Release (nuget.org)`）**：发正式版到 nuget.org。走 **OIDC → 临时 API key**（`NuGet/login@v1` + `id-token: write`），不存长期密钥。
  - **`release-baget.yml`（`name: Release (baget.stdunit.com)`）**：发到私有测试源（预览版/内部验证），沿用 `NUGET_SOURCE` / `NUGET_KEY` 两个 secret。
- 两个工作流都是 `windows-latest` + **`-c Release` 构建与测试**（让"验的"和发的"是同一份产物），测试覆盖 net8.0 + net472（这是 net472 **运行**测试的权威结果），**不在本地强推**。
- `src/publish-packages.ps1` 会：
  - 先校验版本号格式（`<major>.<minor>.<patch>[-<prerelease>]`），不合法立即失败——nuget.org 上的版本不可撤销，手误代价大；
  - `-SkipPush` 可只打包不推送（发版前验证产物），此时不再要求 source/key；
  - `nuget push` 带 `--skip-duplicate`：发布中途失败后重跑，不会因为"包已存在"再挂一次。
- 新增会被发布的包时：把项目名加进 `src/publish-packages.ps1` 列表，并在自己 csproj 里写一行 `<Description>`。

## 二、包元数据

- 统一收口在 `src/Directory.Build.props`：`Authors` / `RepositoryUrl` / `PackageProjectUrl` / `PackageLicenseExpression=MIT` /
  `PackageTags` / `PackageReadmeFile`（仓库根 README 打进包），外加公共编译设置。
  - 此前打出的 nuspec 是 `Package Description` 占位文本 + `authors=包名` + **没有任何 license 字段**。
- **`StdUnit.Tags.OpcUaClient` 例外**：它依赖 OPC UA 栈，授权是 *OPC Foundation MIT License 1.00*（不是 SPDX 标识符），
  因此用 `PackageLicenseFile` 把该 LICENSE 打进包，而不是 `PackageLicenseExpression`。
- **不做符号包（snupkg）**：本仓库打包由 Paket 的 `PackTask` 接管，它不把 pdb 映射进 nuspec，
  `IncludeSymbols=true` 会让 `dotnet pack` 以 `NU5005` 失败（已实测）。
- `TargetFrameworks` 不放进 props（存在 net8-only 项目）；不生成 XML 文档的项目在本项目显式写 `<GenerateDocumentationFile>false</GenerateDocumentationFile>`。

## 三、依赖版本策略

- 依赖用 **Paket**，普遍带 `lowest_matching: true` ⇒ 默认取**最低匹配版本**。
- **本库只声明"最低要求"，不承诺"依赖已审计"**：`dotnet list package --vulnerable` 报出的包（如 net472 侧的 `System.Text.Json 8.0.0`、
  `OPCFoundation.NetStandard.Opc.Ua.Core 1.5.374.126`）是否升级，由**终端开发者**按自己的节奏决定——这与"类库只负责声明下限"的定位一致。
- 升依赖要显式改 `paket.dependencies` 的版本号（`lowest_matching` 不会自动抬版本），再 `dotnet paket install` 刷新 `paket.lock`。
