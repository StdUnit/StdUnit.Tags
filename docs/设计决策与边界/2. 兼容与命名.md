# 兼容与命名

1.0 是**第一个对外稳定的版本**，因此"哪些旧写法还要不要留"必须逐条拍板。本文记录这些决定与理由；
用户可见的变更清单见 [CHANGELOG](../../CHANGELOG.md)，公开面原则见[扩展点](../扩展点.md)。

## 一、已在 1.0 里改掉的

- **`IsScaned` → `IsScanned`**（`ITag` / `ITagCbnt` / `ITagGrp`）。纯 typo 修正，也是 1.0 里对现场影响最大的破坏性变更。
- **异常族重构**：加载期错误统一到 `TagsProjectLoadException` 的 4 个子类（带 `Location` 定位上下文），`TagsProjectSchemaException` 改为 `TagsProjectValidationException` 的派生。**此前按 `TagsProjectSchemaException` 或裸 `Exception` 捕获加载错误的代码必须调整**——详见[错误处理](../异常处理.md)。
- **运行期不再抛裸 `Exception`**：全部改为语义贴近的 BCL 类型；只写 `catch (Exception)` 的调用方不受影响。
- **SimpleFiles 旧 XML 属性 `AutoCreateFile` 移除**：应改用`autoCreateFile`，若仍写旧名，则会在**加载期**抛 `TagsProjectConfigurationException` 并提示改用 `autoCreateFile`。
- **S7 组合（`TagCbnt`）自身必须写绝对地址**：写成相对地址（如 `$$100`）在加载期被拒（`TagsProjectAddressException`）。依据是这种配置**此前从未生效**——`BlockSpecified=false` 只由 `$$` 解析产生，且没有任何代码为组合自身的相对地址去找上层解析，所以收紧不会破坏能工作的配置。
- **`TagChannelDescriptor_S7Extensions` 在 Hjzk / ZLan 里改名**：这两个类都是 S7 的复制粘贴残留（Hjzk、ZLan 各自的描述符转换扩展类却叫 `..._S7Extensions`）。由于只改了类名而不是扩展方法，所以对开发者无感。 

## 二、明确保留的兼容残留

部分早已标记废弃的代码和`typo`问题，理论上可以在`1.0`移除，但是考虑到已经在生产现场使用，所以决定**暂时先不移除**，留待在`2.0`移除：

- `ITagsProject.WriteIntent(string, TagGrpWriteIntent)` 的 `[Obsolete]` 2 参重载（本仓库零调用，但库外有真实调用方）。
- ComScanner 的旧元素名 `<BaundRate>` 的兼容解析（XSD 已把该写法标为非法，新配置请写 `<BaudRate>`）。

## 三、已在 1.1 里改掉的（仅 `StdUnit.Tags.ModbusTcp`）

1.1 只动 Modbus 驱动这一个包（它在 README 里标记为**实验**，因此 `minor` 跳变允许破坏）。
这批**编译层面无破坏**——没有被改名/删除的公开类型（被重构的 `Modbus*DirectTag` / `Modbus*Cbntor` / `interpret` 相关类型
都是 `internal`，公开面只有新增，如 `ModbusBitTagCbntBuilder.Slave`），破坏全部落在**点表（XML）语义**上。共同点是：
修的都是"同一份 XML 换一种写法就得到另一个值、且不报错"的静默错误。

- **`endian` 回归"每个 16 位单元内部两个字节的顺序"**，32/64 位的寄存器顺序改由新属性 `interpret` 表达。
  此前 `endian` 在 16 位与 32/64 位是两套含义，而且 16 位的**组合成员**完全忽略它、**直接测点**却交换两个字节——
  同一份 XML 放 `<TagGrp>` 与放 `<TagCbnt>` 缺省解读恰好相反。依据：两条承载路径语义必须一致（见 `StdUnit.Tags.ModbusTcp/Notes.md` §2）。
  此前依赖"组合成员忽略 `endian`"的配置，请显式写 `endian="BigEndian"` 保持原解读（升级提示见 CHANGELOG）。
- **`TagCbnt` 的 `slave` 属性从此真正生效**：此前位空间构建器只解析、不合成，寄存器空间连解析都没有，于是 `slave="2"` 静默等于 `slave="1"`。
  依据：**此前从未生效**（同 §一里 S7 组合相对地址那条的判断标准），因此收紧不影响任何能工作的配置。
- **参考号 0（`00000` / `10000` / `30000` / `40000`）改为加载期报错**：旧实现 `start -= 1` 对 `ushort` 下溢成 65535，
  `<Tag address="40000">` 会静默指向一个既不报错、也访问不到的点。依据：Modbus 参考号从 1 开始，`x0000` 没有对应的点。
- **`ModbusTcpAddress.ToString()` 的线圈地址补前导零**：`StartPoint=19` 由 `1~20` 改为 `1~00020`——旧串再解析回来是 1 号区域（离散输入）而不是线圈。
- **地址解析的报错更准确**：形状对、内容非法（位号/从站号/参考号越界）时报真正的原因，不再被另一套写法的"未能匹配模式"盖掉。
- **给驱动开发者**：`ModbusBitTagCbntBuilder` / `ModbusRegisterTagCbntBuilder` 的 `WithCbntDescriptor` 现在会消费 `slave`
  并把它合成进 `TagCbnt.StartAddress`；像 ZLan / Hjzk 那样继承这两个构建器的驱动，override 时请调用 `base`。

## 四、命名与风格约定（新增代码请遵守）

- 驱动包的 DI 扩展类**同名** `TagsProject_Extensions`，各在自己的命名空间；驱动名常量集中在 `XxxNames.DriverName`，XML 里的 `driver="..."` 必须与它完全一致。
- 每个驱动的支持注册收口为 `.AddXxxSupport()`，由细粒度注册（`AddXxxChannel` / `AddXxxTagCbntBuilder` / `AddXxxDirectTagBuilder`）组合而成。
- **不要把 `#if` 条件编译铺到调用点，更不要用它去条件修饰公共 API**（那等于给使用方两套签名）——跨框架差异收在 `Compat/` 单点垫片里。
