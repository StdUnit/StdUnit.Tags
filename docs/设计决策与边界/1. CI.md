## CI OS环境

### 发版（`release.yml`）

采用`windows-latest`，同时针对`net472`+`net8`，自动跑完整的构建+测试+发布。注意：不要改成`linux`环境，原因是我们把`release.yml`作为跨平台的兜底。

策略：发布新版只通过云端跑完整的在线自动化构建、测试、发版，不应该在本地强推。

### 构建（`dotnet.yml`）

最初是用 **windows-latest** 跑完整解决方案（net8.0 + net472 + wpf samples+ 覆盖率上报）;

后来短暂引入过 **ubuntu-latest**单独跑net8，变成两种`OS`都跑。但 Windows runner 又贵又常排队，考虑到 `release.yml`（windows-latest）在发版时本来就会全 TFM 跑一遍测试做兜底，而发版时的等待并不是什么不可接受的事，所以现在砍掉了 Windows job，**收敛成单一 Linux job**。

现状：`dotnet.yml` 只有 `ubuntu-latest`，负责构建（覆盖 net472 **编译**）+ `-f net8.0` 测试 + 覆盖率上报（原来在 Windows job 里）——codecov 的组件门槛只按目录划分、与 TFM 无关，所以挪到 Linux 不影响门槛，且 net472 专属分支在 net8.0 构建里不参与编译、不会被误记为未覆盖。

**tradeoff（有意接受）**：

- 云端：**PR/推送**阶段不再**执行** net472 的测试，net472 回归只会在**发版**时暴露； 
- 本地：我本人用`windows`开发，日常性跑自动化测试有兜底；合入PR前务必在`windows`上跑一遍完整自动化测试；改 `Compat/*` 或 `#if NETFRAMEWORK` 分支时务必在 Windows 上一次 `-f net472`。

所以代价可控，换来的好处是测试覆盖率没有降低的前提下日常构建更快。

### net472 的运行测试：`net472-on-mono` job

后来我实测了"把 mono 装到 Linux 上跑 net472"这条路（`VSTest` 需要 `mono` 作为 .NET Framework 的测试宿主），**可行且结果与真框架一致**：

| 环境 | 结果 |
|---|---|
| WSL/Ubuntu 22.04 + mono 6.8.0.105 | `dotnet test -f net472` → **1028 全绿**（8s） |
| Windows 真 .NET Framework 4.7.2 | 1028 全绿 |

于是加了第二个 job `net472-on-mono`：

- **钉 `ubuntu-22.04`**：该镜像**预装 Mono 6.12**，省掉 `apt-get install mono-complete`（当前的 `ubuntu-latest`/24.04 不带 mono，要自己装数百 MB）。镜像退役后改成 `apt-get install -y mono-complete` 即可。
- **`continue-on-error: false`（重要）**：**mono ≠ .NET Framework**。两者在 `System.IO.Ports`（ComScanner 的 net472 路径）、OPC UA 的证书/加密栈、`LogicetLoader` 的 `Assembly.LoadFrom` 分支、`System.Text.Json` 的 net472 资产、全球化/时区等方面都有差异。权威结果仍是 `release.yml`（发版时 windows-latest 全 TFM）+ 开发机 Windows。所以 mono 绿只能说明"大概率没退化"，`continue-on-error`设置为`true`表示**不卡 PR**。默认为`false`。
- 另外 mono 本身已停更（6.x 之后进入维护期）。

顺带说明一个易误解的点：本仓库是 **public**，GitHub 托管的 runner 对公开仓库**免费**——所以 Windows runner 的痛点是**排队**，不是钱。

### 本地在 WSL/Linux 上跑测试

#### `net8.0`下的测试环境

- 通常只需要跑**net8.0**：`dotnet test src/StdUnit.Tags.Tests/StdUnit.Tags.Tests.csproj -f net8.0`。

本项目目前使用`8.0.102`版的`dotnet-sdk`，安装脚本为：
```bash
> curl -L https://dot.net/v1/dotnet-install.sh -o dotnet-install.sh
> chmod +x ./dotnet-install.sh
./dotnet-install.sh --version 8.0.102
```

#### `net472`下的测试环境

Linux 上跑 `-f net472`测试，需要`mono`作为 .NET Framework 的测试宿主，没装就直接 `Could not find 'mono' host` 并让**整次** `dotnet test`（不带 `-f` 时）以 "Test Run Aborted" 收尾。

`ubuntu-22.04`自带`mono`，但`ubuntu-24`没有，可以使用 `apt-get install -y mono-complete`安装。

备注： `mono` 运行时和 `.NET Framework`不完全兼容，`Assembly.LoadFrom`、加密、全局化、线程池等行为都有差异——它的成功与否，都不必然意味着`.NET Framework`的成功或者失败。真正的`net472`+`.NET Framework`需要本机 Windows 手动跑 + `release.yml`自动跑（发版时的 windows-latest）。
